> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `qa` 에이전트 정의는 하나로 유지한 채 review·style·acceptance·gate 역할을 `/qa-check` 포크 세션으로 나누고, Figma 토큰 대조(style)와 fe-dev·be-dev의 pre-check·QA 누락 차단 훅을 추가한다.

**Tech Stack:** Claude Code 2.1.309(agents·skills·hooks), Markdown, Node 24.22(`node:test`, 내장 모듈만), bash + `/usr/bin/jq` 1.7.1, Playwright MCP, Figma MCP(라이브 호출 ≤ 2회), skill-creator grader(`agents/grader.md`).

**Spec:** `docs/specs/2026-10-23-qa-roles-design.md` — 결정 D1–D27, 플랫폼 사실 C1–C19, 미확인 U1–U10. 이 계획의 모든 태스크는 spec과 함께 읽는다.

## Global Constraints

- 에이전트 정의는 `qa` 하나. 새 `agents/*.md`를 만들지 않는다 (D1).
- 진입점 `/qa-check <role> key=value …` — frontmatter `context: fork`, `agent: qa`, `background: false`, `arguments: role` (D10, C13). QA를 부르는 `Agent` 호출에 `name` 파라미터 금지 (C4).
- 역할 = `review | style | acceptance | gate` (D2). 호출자 = orchestrator·fe-dev·be-dev만 (D3).
- 판정 = `PASS | PASS WITH MINOR | FAIL | BLOCKED`, severity = `Critical | Major | Minor | nit`, `waived`는 집계 제외 (D11, D18, D24). 판정 계산은 `scripts/verdict.mjs`만 한다.
- 마커 = 마지막 **텍스트** 메시지 첫 줄 `QA: <verdict> <report-path>` 또는 `QA: N/A — <이유>`(코드 변경이 없을 때만). 같은 줄을 `<report-dir>/status-<name>.txt`에도 쓴다 (`<name>` = 서브에이전트면 agent type, 팀원이면 팀원 이름) (§5.7).
- 리포트 = `<report-dir>/<role>-<sha7>.md` + `<role>-<sha7>.findings.json`, report-dir 기본 `.orchestrator/qa/` (§5.5).
- style = 토큰 레벨 오차 0: px 환산 → **소수 둘째 자리 반올림**(부동소수 표현 정규화이며 허용 오차가 아니다) → 엄격 일치. 색상·타이포 Major, 간격·radius Minor (D6).
- style 기준 소스 우선순위 = Figma 노드 → (없으면) 사용자에게 요청 → mockup (D5). `figma-snapshot=`은 eval 전용.
- acceptance = PRD 없으면 BLOCKED, 시나리오 확정 전 소스 Read 금지, `report-dir` 밖 파일 쓰기 금지 (D4, D25).
- gate = fe: review+style+acceptance / be: review+acceptance / config: review (D7). clean tree에서만 실행. 재사용 조건 `commit == HEAD` ∧ `tree: clean` (D22).
- `agents/qa.md`: `model: sonnet`, `effort: xhigh` (D14).
- Figma MCP 라이브 호출은 계획 전체에서 Task 3의 최대 2회뿐 (C11).
- dev server는 호출자가 띄운다 (D12). QA는 서버를 띄우지 않는다(예외: style의 mockup 정적 서빙, Task 10).
- 사용자 승인 후에만: `~/.claude/CLAUDE.md`·`~/.claude/settings.json`·메모리 파일 수정, repo의 `CLAUDE.md`·`settings.json` 수정, gh 활성 계정 전환, `~/.claude` 배포 (D17).

## Review Focus

1. **훅이 사용자 세션을 가둠** — fe-dev를 메인 세션(`claude --agent fe-dev`)으로 쓸 때의 `Stop`, 팀원일 때, stdin이 깨졌거나 필드가 없을 때는 항상 통과(exit 0, stdout 없음)해야 한다. → Task 15 테스트 `passes non-SubagentStop events`, `fails open on invalid JSON`, `fails open on missing last_assistant_message`.
2. **Figma 수치 표현 노이즈** — `0.15000000596046448`, `1rem`, `letter-spacing: normal`은 표현만 다른 같은 값이고 `line-height: normal`은 숫자와 불일치다. → Task 2 테스트 `normalizeLength: units and float noise`, `letter-spacing normal equals 0`, `line-height normal vs 24 is Major`.
3. **색상 표기 다양성** — `rgb()`·`rgba()`·`rgb(r g b / a)`·`transparent`·대소문자 hex·`#RRGGBBAA`는 같은 색이면 일치, alpha 차이는 불일치, 해석 불가 값은 Not checked. → Task 2 테스트 `normalizeColor: formats`, `unparseable actual goes to notChecked`.
4. **타이포 식별자** — computed `"Roboto", sans-serif` ↔ Figma `Roboto`, Figma 굵기 이름 `Medium`/`Semi Bold` ↔ `500`/`600`은 일치. → Task 2 테스트 `normalizeFontFamily`, `normalizeFontWeight`.
5. **셀렉터 매칭 0개·2개 이상** — 0개는 BLOCKED(셀렉터 이름 명시), 2개 이상은 인덱스로 구분해 전부 비교. → Task 2 테스트 `selector with 0 matches is blocked`, `multiple matches are indexed`.

type Verdict = 'PASS' | 'PASS WITH MINOR' | 'FAIL' | 'BLOCKED'
type Severity = 'Critical' | 'Major' | 'Minor' | 'nit'
interface FindingsDoc { role: 'review'|'style'|'acceptance'|'gate'; blocked: string[]; findings: Finding[]; notChecked: { what: string; reason: string }[] }
interface Finding {
  id: string            // review R-n · acceptance A-n · style S-<target>-<property>-<index>[-<viewport>]
  severity: Severity; status: 'open' | 'waived'; title: string
  where: string         // path:line | <selector>[<i>] @<viewport> | 시나리오 id
  expected?: string; actual?: string; note?: string
  waiver?: { reason: string; by: string; date: string }
  target?: string; selector?: string; index?: number; viewport?: string; property?: string   // style 전용
}
// verdict.mjs
export function computeVerdict(doc: FindingsDoc): Verdict
export function aggregate(verdicts: Verdict[]): Verdict          // [] → throw
// CLI: node verdict.mjs <findings.json>  → stdout "<Verdict>\n", exit 0 / 입력 오류 → stderr, exit 2
//      node verdict.mjs --aggregate <Verdict>...  → stdout "<Verdict>\n"
// compare-styles.mjs
export const PROPS: readonly string[]   // 21개, 아래 순서
export const SEVERITY_BY_PROP: Record<string, 'Major' | 'Minor'>
export function normalizeColor(v: string): { hex: string; alpha: number } | null
export function normalizeLength(v: string | number, ctx: { rootFontSize: number; fontSize?: number }): number | 'normal' | null
export function normalizeFontFamily(v: string): string | null
export function normalizeFontWeight(v: string | number): number | null
export function compareTarget(design: DesignTarget, actual: ActualTarget): { findings: Finding[]; notChecked: {what: string; reason: string}[]; blocked: string[] }
export function applyWaivers(findings: Finding[], waivers: Waiver[]): Finding[]
// CLI: node compare-styles.mjs --design <DesignTarget[]> --actual <ActualTarget[]> [--waivers <Waiver[]>]
//      → stdout FindingsDoc(role:'style'), target 필드로 짝짓는다
interface DesignTarget { target: string; source: string; props: Partial<Record<string, string | number>> }
interface ActualTarget { target: string; selector: string; viewport?: string; count: number; rootFontSize: number; samples: { index: number; props: Record<string, string> }[] }
interface Waiver { selector: string; property: string; figma: string; actual: string; reason: string; by: string; date: string }

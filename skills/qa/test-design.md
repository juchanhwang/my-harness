# Test Design

## 기법 선택 가이드

| 기법 | 언제 쓰나 | 주의 |
| --- | --- | --- |
| 등가 분할 | 입력 범위가 명확할 때 | 같게 처리되는 그룹마다 대표값 하나. 무효 그룹(범위 밖·비숫자·음수·빈 값)도 각각 하나씩 둔다 |
| 경계값 분석 | 범위·길이·개수에 한계가 있을 때 | 경계와 바로 옆 값을 쓴다. 18~65세 허용이면 17·18·19, 64·65·66. `<`와 `<=` 실수가 여기서 드러난다 |
| 결정 테이블 | 여러 조건의 조합이 결과를 정할 때 | 규칙(열) 하나가 케이스 하나다 |
| 상태 전이 | 상태가 이벤트에 따라 바뀔 때 | 무효한 전이(배송중 → 결제 등)를 테스트하는 것이 유효한 전이만큼 중요하다. 전이 표(현재 상태·이벤트·다음 상태·유효 여부)에 불가 조합도 적는다 |
| 페어와이즈 | 파라미터가 많은 설정 조합 | 모든 2개 조합만 커버한다. 3×3×3 = 27개가 9개로 준다 |
| 원인-결과 그래프 | 조건이 3개 이상이고 AND/OR/NOT 의존이 있어 결정 테이블이 너무 커질 때 | |
| 탐색적 테스트 | 명확한 스펙이 없을 때 | `exploratory-testing.md` |

## 엣지 케이스 체크리스트

- null / undefined
- 빈 배열 / 빈 객체, 원소 1개, 최대 원소 수
- 경계값: `0`·`1`·`-1`, 빈 문자열·한 글자·최대 길이·최대 길이 + 1, 월말·월초·윤년, 자정·일자 변경선
- 동시성: 같은 동작의 동시 실행(더블 클릭·중복 제출), 같은 리소스의 동시 수정
- 네트워크 장애·타임아웃: 요청 실패, 느린 응답에서 로딩·에러 상태가 나오는가 (E2E 재현은 `e2e-testing.md`의 네트워크 가로채기)

## 실전 팁

- 기법을 겹쳐 쓴다: 등가 분할로 그룹을 나누고, 경계값으로 각 그룹의 경계를 보고, 결정 테이블로 조건 조합을 덮고, 상태 전이로 플로우를 확인한다.
- 음성 테스트를 빠뜨리지 않는다: 유효하지 않은 입력, 허용되지 않은 상태 전이, 권한 없는 접근, 시스템 제한 초과. 양성 테스트는 시스템이 할 수 있는 것을, 음성 테스트는 하면 안 되는 것을 검증한다.
